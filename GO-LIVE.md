| S0 | 🔴 **Any signed-in user could promote themselves to admin — fixed in `042`, NOT YET IN PRODUCTION** | The policy `"Users can update their own profile"` was `for update using (auth.uid() = id)` with **no `WITH CHECK`**. Postgres then reuses `USING` as the check, and `auth.uid() = id` is still true after the row changes — so the policy permitted updating *any column* of your own row, `portal_role` included. One request (`update profiles set portal_role='admin' where id=auth.uid()`) made a KA an admin, and from there every branch's sales, every approval and every roster.
